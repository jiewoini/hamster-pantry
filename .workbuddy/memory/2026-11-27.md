# 2026-11-27

## 审核驳回：内容安全 / UGC

驳回原文（模板话术）：小游戏在用户自定义昵称、聊天室、个人资料签名、个人空间描述等场景，未具备过滤政治有害、色情、赌博违法等不当信息的机制，要求接入 `imgSecCheck` / `msgSecCheck` 或其他审核手段。

**根因**：本游戏没有聊天室、签名、空间，也没有图片上传或文字发布。全项目唯一自由输入是"小猫档案"里用 `wx.showKeyboard` 给猫起名（`game.js` 的 `requestName`，`view.js` 的 `editName`）。昵称只写本机 storage。审核员看到输入框后套用了 UGC 模板。

**处理：从源头消除 UGC，不硬接 API**

- `game.js`：删除 `requestName` 及 `wx.showKeyboard / onKeyboardConfirm / onKeyboardComplete`，包内已无键盘输入。
- `view.js`：
  - 新增 `CAT_NAME_POOL`（40 个预设名）、`NAME_PICK_COUNT = 20`。
  - `editName()` 改为打开自绘面板；新增 `rollNames()`（洗牌取 20）、`pickName(name)`、`drawNamePicker()`（4×5 网格 + 换一批 / 收起）。
  - `editProfile()` 初始化 `namePickerOpen / nameChoices`；`drawProfile()` 末尾按需绘制面板。
  - 文案"改名字"→"换名字"，保存失败提示改为"名字不太合适，换一个试试"；去掉无用的 `this.naming` 判断。
- `preview.html` / `output/shot.html`：移除 `requestName`；shot.html 新增 `scene=profileName` 场景。

**验证**：`node --check view.js / game.js` 通过，15 项测试全过；无头渲染确认名字面板 20 项不重叠、换一批/收起可用、无溢出。预览图 `output/shots/小猫档案_改名前.png`、`小猫档案_选名字面板.png`。

**事故与恢复**：重命名中文截图时误用 `rm -f *.png`，把 `output/shots` 下 4 张寻物 PNG 删了（jpg 备案图未受影响）。已用 `shot.html` 全部重渲染并恢复：找找找_开始页/游玩页/提示弹窗/完成页。以后清理截图禁止用通配符，只能按精确文件名删。

**版本策略**：重新上传 `1.0.3`，只带"移除输入 + 预设名字"；寻物若一起上，版本说明加一句"新增单机寻物玩法，无 UGC"。复审文案已写入 `SUBMISSION_CHECKLIST.md` 8.8 节。

### 方案调整：用户要保留自由起名

用户明确"想让人家在合理的范围自由写名字"，于是从"移除输入"改为"保留输入 + 内容安全校验"。

官方接口确认：小游戏可用 `security.msgSecCheck`（云调用 `cloud.openapi.security.msgSecCheck`），必须服务端调用；云开发有免费环境（6 个月续期），基础套餐 19.9 元/月。

实现：
- 新建 `cloudfunctions/checkName/`：`index.js`（取 `OPENID`，`scene:1`、`version:2`，`87014`/`risky`/`review` 拒绝，异常返回 `ERROR` 不放行）、`config.json`（openapi 权限 `security.msgSecCheck`）、`package.json`（wx-server-sdk ~2.6.3）。
- `game.js`：`wx.cloud.init`；恢复 `requestName`（`wx.showKeyboard`）；新增 `checkName`（本地 `localNameCheck` 规则 + 云函数），云开发不可用返回 `UNAVAILABLE`。
- `view.js`：`editName()` 输入后异步校验，`nameChecking` 期间拦截保存；被拒按错误码提示；`NETWORK/UNAVAILABLE/ERROR` 自动打开推荐名字面板兜底。新增 `nameRejectText()`。
- `project.config.json`：加 `"cloudfunctionRoot": "cloudfunctions/"`。
- `PRIVACY_NOTE` 更新：昵称保存前经微信内容安全接口校验，不存储到自有服务器、不公开展示；`drawPrivacy` 卡片加高到 300、行距 21、字号 11，避免文字压按钮。

验证：`node --check game.js / view.js / cloudfunctions/checkName/index.js` 通过，15 项测试全过；渲染确认隐私弹窗文字完整不压按钮。截图 `隐私指引_内容安全版.png`、`小猫档案_自由起名版.png`。

### 最终方案：改用自有后端（用户不想出钱）

查到官方规则：**云开发免费环境在小游戏发布上线后第 15 天到期**，之后必须转付费 19.9 元/月。所以放弃云开发，改复用已有 `https://api.ooptop.top` 后端（`admin-backend`，Java 8 + Spring Boot + RestTemplate，已有 `WECHAT_APP_ID/SECRET` 与 `code2-session-endpoint`）。用户确认走这条。

后端新增（编译通过 `mvn -DskipTests compile`）：
- `service/ContentSecurityService.java`：code2session 换 openid；`access_token` 内存缓存（提前 300s 过期，40001/42001 失效重试一次）；调 `POST https://api.weixin.qq.com/wxa/msg_sec_check`（`scene:1`、`version:2`）。`87014`/`risky`/`review` 拒绝，其余异常返回 `ERROR` 不放行。缺 appId/secret 时：dev 模式放行、生产返回 `CONFIG` 拒绝。
- `controller/ContentSecurityController.java`：`POST /api/content/check-name`，匿名可访问（`AdminAuthInterceptor` 只拦 `/api/admin/**`）。
- `dto/CheckNameRequest.java`：content ≤32、code ≤128，`@NotBlank`。

小游戏端：
- `game.js`：新增 `SEC_CHECK_URL = 'https://api.ooptop.top/api/content/check-name'`；`checkName` 先 `localNameCheck`，再 `wx.login` 取 code → `wx.request` POST `{content, code}`；全部失败路径都拒绝。
- 移除 `cloudfunctions/` 目录与 `project.config.json` 的 `cloudfunctionRoot`。

**待用户操作**：后端确认 `WECHAT_APP_ID/SECRET` 且 `WECHAT_DEV_LOGIN_ENABLED=false` → `mvn -DskipTests package` 部署 → 小游戏后台把 `https://api.ooptop.top` 加进 request 合法域名 → 隐私指引补"昵称用于内容安全校验" → 真机验正常/违规/断网。清单 8.8 已按此重写。

### 共用后端的隔离修正（用户追问）

用户问 `admin-backend` 是他**另一个小程序**在用的后端，会不会相互影响。

结论：路由/数据层不影响（只新增 `/api/content/check-name`，不改现有 Controller/Service，不新增实体，JPA 不会改表）。但发现一个致命坑：上一版复用了 `app.wechat.*` 的 appid/secret，而 `wx.login` 的 code 只能用**同一 appid** 换 openid，混用会 invalid code。

已修：
- `application.yml` 新增独立配置段 `app.paw.*`：`PAW_APP_ID` / `PAW_APP_SECRET` / `PAW_CODE2_SESSION_ENDPOINT` / `PAW_DEV_MODE`。原有 `app.wechat.*` 一律不动。
- `ContentSecurityService` 改读 `app.paw.*`；增加全局限流 120 次/分钟（`allowCheck()`，防止被刷影响同服务器业务）。
- `mvn -DskipTests compile` 通过。
- 清单 8.8 补了"与另一个小程序共用同一后端怎么保证不互相影响"一节，并修正步骤编号。

遗留提醒：部署重启会短暂中断另一个小程序，需选低峰期；`PAW_APP_SECRET` 需用户在小游戏后台生成后配到服务器。
